# Service Desk Simulator – Daily Practice Log & Portfolio Project

**Hands-on IT Support Training** | Live Service Desk Simulation

This repository documents how I use [ServiceDesk Simulator](https://www.servicedesk-simulator.com/) for **daily practice** of real-world help desk / service desk skills.  

The platform acts as a “flight simulator” for IT support — I take live AI voice calls, work realistic tickets, and resolve user issues using the same tools found in an actual enterprise environment.

---

## Why I Practice Here Daily

Watching videos and reading documentation only goes so far.  
ServiceDesk Simulator forces me to:

- Think under pressure while on a live call
- Navigate multiple tools at once
- Follow proper ticket workflow and documentation
- Use Active Directory / Directory tools correctly
- Remote into user machines and fix issues
- Fall back on the Knowledge Base when I don’t know the solution

This daily practice builds the exact muscle memory and confidence needed for a real Level 1 / Level 2 Service Desk role.

---

## My Daily Practice Workflow

### 1. Start a Practice Shift
- Open [servicedesk-simulator.com](https://www.servicedesk-simulator.com/)
- Review the **Ticket Queue** for open incidents
- Monitor for incoming **AI voice calls** and voicemails

### 2. Take Live Calls
- Answer AI-powered voice calls from simulated end users
- Practice professional communication, active listening, and call control
- Gather required information (user identity, device, error messages, impact)
- Create or update tickets based on the conversation

### 3. Resolve Tickets Using Real Tools

I treat every ticket the same way I would on a real service desk:

| Tool                  | How I Use It                                      | Typical Scenarios                          |
|-----------------------|---------------------------------------------------|--------------------------------------------|
| **Directory**         | Reset passwords, unlock accounts, create/modify users, manage group membership | Password resets, account lockouts, onboarding, access requests |
| **Remote Desktop**    | Connect to the user’s machine, install software, change settings, troubleshoot hardware/software | Driver issues, application problems, printer mapping, configuration changes |
| **Knowledge Base**    | Search SOPs and articles when I don’t know the solution | Unfamiliar errors, standard procedures, escalation criteria |
| **Ticket Queue**      | Prioritize, document steps taken, update status, close tickets | All incidents and service requests         |
| **Server Room**       | Restart services, check infrastructure health     | Server-side issues, service outages        |
| **Asset Management**  | Look up devices, warranties, hardware details     | Hardware replacements, inventory questions |

### 4. Documentation & Closure
- Always document exact steps taken inside the ticket
- Confirm resolution with the user (or simulated confirmation)
- Close the ticket only when the issue is fully resolved
- Note any knowledge gaps so I can research them after the session

## Skills I Practice Every Session

- **Active Directory / Directory administration** – password resets, unlocks, group management, user onboarding
- **Remote support** – connecting via Remote Desktop and fixing issues live
- **Ticket management** – prioritization, proper documentation, SLA awareness
- **Communication** – handling frustrated users, explaining technical steps clearly, call control
- **Troubleshooting methodology** – gathering information → isolating the problem → applying the fix → verifying
- **Knowledge Base usage** – knowing when and how to search for existing solutions instead of guessing
- **Multi-tasking** – managing calls, tickets, and tools simultaneously

## Practice Tracking Ideas

I recommend tracking your sessions so you can show progress on a resume or in interviews:

- Number of tickets resolved per session
- Number of live calls taken
- Types of issues handled (password resets, network, hardware, software, AD)
- New Knowledge Base articles learned
- Time spent practicing each day

Example daily log format:

```
Date: 2026-07-30
Duration: 45 minutes
Tickets resolved: 6
Calls taken: 3
Tools used: Directory, Remote Desktop, Knowledge Base
Notes: Practiced password reset workflow and printer driver remote install
```
